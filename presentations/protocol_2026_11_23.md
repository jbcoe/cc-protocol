# Polymorphism

Polymorphism (from the Greek for "many forms") is the ability of different objects to
respond to the same function call in their own specific ways.

C++ supports polymorphism at compile-time and runtime.

---

# Compile-time Polymorphism

Overloaded functions or function templates allow the compiler to determine which
function to call during compilation:

```c++
double func(const A& a);
double func(const B& b);
```

```c++
template <typename T>
double func(const T& t);
```

We won't look at compile-time polymorphism in this presentation.

---

# Closed-set Runtime Polymorphism

In C++ we can use `std::variant` and `std::visit` to implement closed-set polymorphism:
runtime dispatch for a predefined set of types.

```c++
template<class... Ts> struct overload : Ts... {
    using Ts::operator()...;
};
```

```c++
std::variant<A, B, C> myObject;

std::visit(overload {
        [](const A&) { ... },
        [](const B&) { ... },
        [](const C&) { ... }
    },
    myObject);
```

# Open-set Runtime Polymorphism

A derived class can override member functions of a base class.

We can use the `virtual` keyword to require runtime resolution of a function.

A derived-class member function can then be called from a base class pointer or reference.

```c++
class Shape {
  public:
    virtual int sides() const = 0;
};
```

```c++
class Square : public Shape {
    int sides() const { return 4; }
};
```

```c++
class Triangle : public Shape {
    int sides() const { return 3; }
};
```

# Manual virtual dispatch

We can implement our own form of runtime dispatch using a function pointer.

```c++
class Cat {
 public:
  std::string_view noise() const { return "Meow"; }
};
```

```c++
class AnimalPtr {
  void* data_;
  std::string_view (*noise_func_)(const void* data);
  ...
```

---

# Manual virtual dispatch (continued)

The constructor of `AnimalPtr` sets the function pointer to a function
that calls the appropriate member on `data`.

```c++
 public:
  template <typename T>
  AnimalPtr(T* t)
      : data_(t), noise_func_(+[](const void* data) -> std::string_view {
          return static_cast<const T*>(data)->noise();
        }) {}

  std::string_view noise() const { return noise_func_(data_); }
};
```

---

# Manual virtual dispatch (continued)

As defined, the wide pointer will increase in size for each member function we add:

```c++
class WidePtr {
  void* data_;
  rt0 (*func_0_)(const void*, args0);
  rt1 (*func_1_)(const void*, args1);
  ...
};
```

Like many problems in computer science, we can solve this with another
layer of indirection.

---

# Manual virtual dispatch with a vtable

```c++
struct vtable {
  rt0 (*func_0_)(const void*, args0);
  rt1 (*func_1_)(const void*, args1);
  ...
};
```

```c++
class WidePtr {
  void* data_;
  const vtable* vtable_;
public:
  template <typename T> WidePtr(T* t);
  rt0 func_0(args0);
  rt1 func_1(args1);
};
```

---

# Construction of the vtable

For each type `T` we have a compile-time static vtable instance
that the vtable pointer will point to.

The wide pointer does not manage the vtable lifetime.

```c++
template <typename T>
WidePtr(T* t) : data_(t) {
  constexpr static vtable vtable_for_type = {
    .func_0_ =
      +[](const void* data, args0 a) {
        return static_cast<const T*>(data)->func_0(a);
      },
    .func_1_ =
      +[](const void* data, args1 a) {
        return static_cast<const T*>(data)->func_1(a);
      },
  };
  vtable_ = &vtable_for_type;
}
```

---

# Dispatch with a vtable

Using the two-pointer-big wide pointer, member functions
can be dispatched at runtime using the vtable:

```c++
rt0 WidePtr::func_0(args0 a) {
  return vtable_->func_0_(data_, a);
}

rt1 WidePtr::func_1(args1 a) {
  return vtable_->func_1_(data_, a);
}
```

---

# Non-intrusive polymorphism with type erasure

The runtime polymorphism we've defined with our manual vtable does
not require types `T` to have been annotated with `virtual` keywords
or to inherit from a base class.

The derived type is "erased", all necessary information is stored in
the vtable.

We can manually implement intrusive polymorphism using a vtable.

---

# Manual intrusive runtime polymorphism

```c++
struct vtable {
  rt (*func_)(const void*, args);
  ...
};

class Base {
 protected:
  const vtable* vtable_;
 public:
  rt func(args a) const {
    return vtable_->func_(this, a);
  }
};
```

Deciding which functions go into the vtable is akin to use of the `virtual` keyword.

---

# Manual intrusive runtime polymorphism (continued)

Our derived type defines a vtable and implements the necessary function(s):

```c++
class Derived: public Base {
 public:
  Derived() {
    constexpr static vtable vtable_for_type = {
      .func_ =
        +[](const void* data, args a) {
          return static_cast<const Derived*>(data)->func(a);
        }
    };
    vtable_ = &vtable_for_type;
  }

  rt func(args a) const {
    return /* some implementation */;
  }
};
```

```c++
Derived d;
Base& b = d;
b.func(a); // calls `func` from d
```

# Runtime Polymorphism in Rust

Rust also supports runtime polymorphism with traits:

```rust
trait Fooable {
    fn foo(&self, i: i32) -> i32;
}
```

```rust
struct MyFoo {
    value: i32,
}

impl Fooable for MyFoo {
    fn foo(&self, i: i32) -> i32 {
        self.value + i
    }
}
```

```rust
fn foo_it(fooer: &dyn Fooable) -> i32 {
    fooer.foo(1)
}
```

---

# Implementing traits for types

In Rust, a trait can be implemented for a type in the crate that
defines the type or in the crate that defines the trait.

In both cases runtime polymorphism is implemented using a wide pointer.

The size of `&dyn Fooable` is twice the size of `&MyFoo`.

# Polymorphism in Python

To a rough approximation function calls in Python are resolved dynamically
by looking up a name in a dictionary stored in each object.

We have duck-type polymorphism: if the name can be found, it can be used.

Python's type system was retrofitted and supports duck-typing with `typing.Protocol`.

```python
from typing import Protocol

class Fooable(Protocol):
    def foo(self, i: int) -> int: ...
```

An author can tell the type checker which methods (member functions) are
needed rather than use `Any` (which opts out of type checking).
